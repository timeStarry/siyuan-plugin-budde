# Budde 工作台交互与前端设计

状态：用户已选择「聚焦一个类型」，并明确确认按本说明制作独立可点击原型；正式插件 UI 修改仍未获授权。
日期：2026-11-11。

## 1. 意图与边界

用户在思源阅读、写作时先留下标题，再决定哪些值得推进。工作台应让记录足够轻、推进有焦点、长内容回到思源，而不是增加一个独立任务应用。

本轮交付是**独立可点击设计稿及说明**。不修改正式插件 UI、核心业务、持久化或宿主桥接；正式 UI 落地另行确认。需求源头仍是 [Budde｜需求文档](siyuan://blocks/20261111001236-5io3spm)，本说明只确定交互和呈现。

目标：
- 标题即记录，不强制类型配置、说明、下一步或笔记关联。
- 看板一次聚焦一个类型，避免所有空列纵向堆叠。
- 保留跨类型推进列表，使下一步容易看见。
- 详情按需展开，不把列表变成大表单，也不牺牲草稿与冲突保护。
- 继承思源字体、语义颜色与轻量界面习惯。

非目标：账户、独立同步、独立应用导航、移动端发布、浏览器端发布、统计仪表盘、日历/截止日期、子任务、人工卡片排序、AI、导入、永久删除、主动新建思源文档。窄分屏适配不是新增移动端支持。

约束来源：[产品上下文](../../../PRODUCT.md)、[既有视觉方向](../../ui-direction.md)、[业务决定](../../decisions.md)。技术继续使用 TypeScript DOM/CSS，不引入框架、线上字体或远程素材。

## 2. 方案与已作选择

三种方案以相同的功能、主题和示例语义比较：

| 方案 | 空间组织 | 取舍 |
| --- | --- | --- |
| **聚焦一个类型（用户选择）** | 顶部主视图；看板内类型索引；当前类型阶段列；可关闭详情 | 单一类型更专注，不同类型需切换；跨类型工作由推进清单承接 |
| 先看下一步 | 推进清单为主要工作入口，看板同级可达 | 更适合逐项行动，但生命周期分布退居其次 |
| 保留多类型总览 | 多种类型看板纵向排列、按需折叠 | 保留全局分布，但展开多组后仍会较长 |

用户已在布局比较页选择第一种。选择覆盖布局方向，不自动等于批准未展示的交互细节或修改正式插件。

## 3. 信息架构

```text
Budde    想法池 | 看板 | 正在推进                       归档  更多
┌ 记下一个想法，标题就够了 ……  [新事项类型：通用] [记下来] ┐
├ 当前视图名称 / 小计                         标题搜索 / 筛选 ┤
│ 看板模式：类型索引  │ 当前类型的阶段列 …                │ 详情 │
│ 列表模式：事项标题 / 类型与阶段 / 已填写的下一步          │ 按需 │
└───────────────────────────────────────────────────┘
```

- 默认打开「想法池」，保持产品首先是记录与找回的定位。用户已选布局并不意味着把看板设为默认启动页。
- 三个主视图：想法池、看板、正在推进。归档作为安静的独立集合入口，不再与推进视图组合成必然为空的复选条件。
- 「更多」包含管理类型与阶段、JSON 导出。类型管理也可从看板类型索引末尾到达，但不增加一套应用级侧导航。
- 搜索只匹配事项标题；类型筛选与搜索条件只作用于正在查看的集合，不搜索思源正文。
- 保留简短结果小计，不增加统计卡片或类型彩虹配色。

### 想法池

默认列出全部未归档事项，不把池子改成只有未推进事项的收件箱。提供「全部 / 未开始推进」快捷筛选及类型筛选；这些是查看方式，不改业务状态。

一行依次突出标题、类型和原阶段、必要的暂停/完成/复查提示、已填写的下一步。未推进事项可显式「开始推进」。不长期为每行展示阶段选择器与多个状态按钮。

### 看板

左侧紧凑索引列出类型及当前条件下的事项数，只展开选中的一种类型。类型改名不改标识；渲染和选择以 ID 为准，不依赖名称唯一。

每列显示该类型原有阶段名与计数；卡片突出标题、下一步、暂停/复查文字提示和关联数量。已完成事项保留在完成属性对应的列。阶段少于或多于四列时不伪造列、不映射阶段。

看板集合为已开始推进且未归档的事项，包括暂停和完成事项。卡片拖动只改变本类型阶段，不暗示同列人工排序；卡片菜单和详情阶段选择器提供键盘等效操作。跨类型移动必须在详情中同时明确选择目标类型及其阶段。

### 正在推进

跨类型列出 `promoted && !paused && !archived && !completed` 的事项，展示原类型、原阶段和下一步。初始阶段、空下一步都不妨碍进入此集合；没有下一步时显示轻量占位，不催用户填表。

### 归档

显示所有已归档事项，支持标题/类型查找与打开详情。提供「移出归档」；恢复不改变原阶段或暂停状态，因此不保证自动进入推进列表。无永久删除入口。

## 4. 核心操作与反馈

### 记录

- 输入标题即可提交。记录栏显式显示新事项类型；通常为通用，通用已被删除时遵循核心的首类型回退规则。
- 创建类型与内容筛选分开表达，不偷偷跟随筛选变化。这是本方案提出的界面调整，不修改核心默认规则。
- Enter 记录，中文输入法组词确认不提交；标题不能为空且沿用核心 500 字上限。
- 保存中禁止重复提交，保留文字；成功后清空并恢复记录焦点；失败保留输入。响应丢失重试沿用同一请求标识。
- 无论在哪个主视图记录，创建都不自动开始推进。在看板/推进视图反馈「已记入想法池」，并提供查看入口，而不是把新事项悄悄提升。

### 选择与草稿

- 点击标题打开详情；再次选择同一事项不重置表单。
- 详情从上到下：标题、类型/阶段、下一步、说明、思源关联、保存区、状态操作。
- 使用显式保存，不改为自动保存。未保存、保存中、已保存、失败、版本过期分别呈现；成功只在命令提交成功后显示。
- 选中其他事项、关闭详情、切换主视图或看板类型会关闭/替换详情：若有草稿，先显示「保存后继续 / 放弃修改 / 继续编辑」；干净详情直接切换。保存失败或冲突时不继续原跳转。
- 标题搜索和一般筛选不清空详情或草稿。选中事项暂不属于当前结果时，详情保留，并显示简短说明；不自动选择另一条。
- 保存期间禁用该表单及重复状态操作，避免中途新输入被已完成的请求覆盖。

### 阶段、暂停、归档、复查

- 「开始推进」不改阶段。暂停、恢复、归档和移出归档保留原阶段。
- 卡片改阶段遇到该事项的未保存草稿时，不绕过草稿；先明确保存或继续编辑，不能覆盖输入。
- 详情中的暂停、归档、复查若有草稿，明确确认「保存修改并执行」后沿用同一更新命令；可取消，不静默丢弃或悄悄保存。执行失败保持表单及原状态。
- 14 天复查沿用当前规则：浏览不刷新；推进后的阶段/下一步变化及明确复查确认可刷新；未推进的纯标题事项不提示复查。
- 版本冲突保留本地全部输入，提示内容已变化。「放弃草稿并读取最新版本」说明后果并确认后再读取；不覆盖他人修改，不宣称自动合并。

### 思源关联与设置

- 优先显示已关联笔记的可打开列表；「关联笔记」再展开目标与资料/成果角色输入。
- 添加/移除关联进入草稿，保存后生效；移除关联不删除思源正文。失效或无法打开反馈错误，不能悄悄移除原关联。
- 仅支持已有文档/块关联，不增加假可用的「新建文档」按钮。
- 类型/阶段管理使用对话框。配置草稿在刷新和保存失败时保留，版本冲突明确重新读取；关闭脏配置同样确认放弃。
- 类型至少一种、每类型阶段至少一个；删除非空类型不允许。删除被引用阶段须先选择迁移目标，影响范围包括归档事项；初始阶段和完成属性不因重排被重定义。
- JSON 导出沿用现有完整数据语义，明确不含思源笔记正文。

## 5. 视觉与尺寸

采用既有的纸面、石墨、淡墨与嫩芽绿气质，不重新设计品牌。以下数值是设计提案，由构建者按实际字体和宿主容器微调，不改变结构与信息优先级。

- 字体继承宿主；独立稿仅用系统字体回退。页名 20px/600，事项 14px/500，正文 14px，次要信息不低于 12px。
- 4px 基础间距，主边距 24px，紧凑容器 16px，卡片间距 8–12px。主要按钮/输入高 40px，图标按钮目标至少 32px。
- 看板类型索引约 136px，详情约 320px，阶段列最小约 220px，列间距 12px。优先让卡片标题和下一步可读，而非挤满全部列。
- 平面背景、轻边框、4–6px 圆角；没有装饰性投影、渐变背景、营销大标题或图片。
- 颜色映射至 `--b3-theme-background`、`--b3-theme-surface`、`--b3-theme-on-background`、`--b3-theme-on-surface`、`--b3-border-color`、`--b3-theme-primary` 等语义变量。独立稿提供浅/深回退值，不固定白底。
- 选中用边框/背景辅以可识别状态，暂停、完成、错误有文字或图形，不仅用颜色。所有控件有清楚的焦点、悬停、禁用状态。
- 长标题可换行；下一步按空间裁切但在详情完整可见；关联显示标题，完整目标可查看，不让长链接撑破布局。

## 6. 窄分屏与键盘

使用工作台容器宽度决定布局，而不把整个思源窗口宽度当作插件可用宽度。

- 容器约 1200px 以上：索引、看板和右侧详情可同时存在；无选中事项时详情不占空位。
- 约 720–1199px：保留看板类型索引；详情作为右侧覆盖层打开，不继续挤压卡片。覆盖层有清楚标题、关闭与遮罩，约束焦点。
- 小于约 720px：类型索引收成看板上方的类型选择；详情占当前插件容器，提供返回列表，保留此前选中和滚动位置。
- 看板只在内容区域内部横向滚动，工作台外层不溢出。列表和详情内部独立滚动，不把详情堆在列表上方将正文推到屏外。
- 打开详情将焦点移入标题/首个操作，关闭后返回原事项；对话框焦点进入/返回明确。Escape 按相同草稿规则退出，不绕过确认。
- 不依赖拖动或悬停才能操作；Tab 可达卡片菜单、阶段选择、关联和保存。结果/保存反馈使用适当的状态或警告语义，不在每次输入时重复播报。

## 7. 独立设计稿的实现边界

这部分是构建者的技术建议，非用户要求新增技术栈：

- 另置设计稿源码与独立构建入口，输出可直接打开的 HTML、CSS、脚本，不替换正式 `src/ui` 或插件构建入口。
- 可复用只读导入的 `BuddeService` + `MemoryStore`，所有命令仅写入演示内存，刷新重置；不调用文件存储和真实 SiYuan API。
- 单一合成状态派生各视图与计数，含未推进、初始阶段已推进、空下一步、暂停、完成、归档与需复查样例。原型顶端明确显示「示例数据，刷新重置」。
- 模拟笔记桥接只展示演示反馈，不打开或修改真实文档。没有真实工作空间正文、凭据或个人数据。
- 将主题切换、模拟保存失败、模拟外部版本变化和重置数据放在标明「演示工具」的独立折叠区，不混入产品功能。
- 导出可输出演示 JSON；设置与事项交互走已有命令/版本规则，不重写一套看似相同的业务语义。
- 不修改核心、平台适配、正式 UI、生产存储格式、依赖或支持范围。独立稿的示例失败/冲突演示不是思源真实宿主验收。

## 8. 验收与交付

交付：本说明、独立可点击设计稿、打开/构建方法、浏览器截图及结果摘要。完整场景见 [设计验证清单](../../design/workbench-validation.md)。

必须实际检查：
1. 连续标题记录、中文输入法、失败保留与重试。
2. 三主视图/类型/搜索、初始阶段推进、阶段修改和跨类型明确选阶段。
3. 显式保存、脏数据跳转/关闭、保存失败、外部版本冲突与明确重新读取。
4. 暂停/归档/恢复的阶段保持、关联草稿与导出、生命周期设置可达。
5. 1440×1000、1024×768、720×900、480×800 窄分屏；浅深主题；焦点及非拖动操作；外层无横向溢出。

已知基线：本轮未修改正式代码，但一次 `pnpm check` 在原有 24 并发存储测试出现 `LOCK_TIMEOUT`（17/18 测试通过），构建因测试失败未执行；同时出现 pnpm 自动依赖核验的存储路径/无 TTY 警告。此项记录为基线问题，不将其算作设计稿已通过或擅自重装依赖、改写文件锁。随后单独复跑该 24 并发用例通过（1/1，约 1.3 秒），但单用例通过不等于整套 `pnpm check` 已通过；本轮不据此修改核心或清除此前失败记录。
