## 用户任务与设计目标

用户在思源中阅读、写作和整理资料，想法不必马上成为要执行的任务。

1. 记录：输入标题即可保存，继续下一条，不强制打开详情。
2. 找回：通过标题、类型和管理状态缩小范围，不暗示搜索了思源正文。
3. 决定推进：显式开始推进；不用填写说明、下一步或建立文档。
4. 推进：按当前类型的阶段移动事项，跨类型列表查看下一步。
5. 展开：在需要时补充下一步、说明与笔记关联，长内容仍在思源里。
6. 收纳：暂停不丢阶段，归档移出日常视图，并有明确找回入口。

## 本轮布局候选

所有方案使用同一套主题、内容和业务语义，只比较空间组织。

- **聚焦一个类型**：顶部切换三个主视图；看板内用紧凑类型索引切换生命周期；详情按需出现在右侧。适合深入推进一个类型，跨类型事项由推进列表汇总。
- **先看下一步**：推进清单作为工作的主入口；看板保持同级可达，重点在逐项行动，而非阶段分布。
- **保留多类型总览**：类型看板纵向排列，折叠不关注的类型；保留整体分布，但同时展开时仍可能较长。

用户已选择「聚焦一个类型」。尺寸、响应式策略、组件与状态的完整方案见已确认的 [工作台设计说明](../superpowers/specs/2026-11-11-workbench-design.md)，下一步制作独立可点击设计稿。

## 各方案共同的交互规则（待设计确认）

### 快速记录

- 在主视图中始终可达，但不抢走搜索或详情编辑时的焦点。
- 通常默认创建通用类型；若通用类型已被删除，遵循核心的第一种类型回退规则。记录栏必须显式显示实际创建类型。创建类型与内容筛选分开表达，不把筛选条件偷偷当成创建默认值。这是拟议的界面交互调整，核心创建命令和默认规则不变。
- Enter 提交；中文输入法组词确认不触发提交。禁止空白标题。
- 保存中保留标题并阻止重复提交；确认成功后清空、恢复输入焦点。
- 失败保留输入，提供重试；响应丢失时沿用原请求标识。
- 在看板或推进列表中记录标题，仍然只是记录，不隐式开始推进；成功反馈说明已记入想法池，并提供查看入口。

### 想法池与查找

- 默认显示全部未归档事项，提供“未开始推进”的快捷筛选。
- 标题是主信息；类型、原阶段和管理状态是次信息；已填写的下一步可补充展示。
- 不为每条事项长期露出阶段选择器和多个按钮。常用操作按需出现，键盘焦点时同样可达，不能只依赖鼠标悬停。
- 归档是明确的集合入口，不与“正在推进”组合成一个逻辑上必然为空的筛选。
- 空池、搜索无结果、筛选无结果、无推进事项和无归档事项使用不同文案与恢复操作。

### 类型看板

- 每种类型维持自己的阶段名称、顺序与完成属性，不做跨类型阶段映射。
- 看板显示已开始推进且未归档的事项，保留完成列事项。
- 卡片突出标题、下一步及必要的暂停/复查提示；在列内避免重复显示已有列标题。
- 拖动只改变阶段；提供阶段菜单或详情选择器作为键盘等效操作。
- 不在设计稿中加入未获业务支持的同列人工排序、子任务或进度百分比。
- 类型/阶段设置不长期占用主工作区；修改完成属性、迁移或删除前清楚说明影响范围。

### 详情与笔记

- 只在选中事项时展开；标题在前，类型与阶段相邻，下一步优先于较长的说明。
- 沿用显式保存，以“未保存 / 保存中 / 已保存 / 保存失败 / 版本冲突”区分状态。
- 切换事项、关闭详情、切换视图或归档时，不静默丢弃草稿；有脏数据时提供保存、放弃或继续编辑的明确选择。
- 版本冲突保留本地输入；重新读取必须明确说明将放弃哪些草稿，不自动覆盖。
- 思源笔记优先显示可打开的关联列表，“添加关联”按需展开输入表单。
- 关联失效反馈不能移除原关联；移除关联不等于删除思源正文。
- alpha.1 没有实现的主动新建思源文档，不伪装成设计稿中已可用的正式能力。

### 窄分屏与主题

- 继承思源字体和语义色，浅色与深色均设计，不固定白底或强行覆盖宿主强调色。
- 详情不把正文向下推到不可见位置；窄分屏采用覆盖式详情或独立详情层，并保留返回位置。
- 看板允许内部横向滚动，不允许工作台外层横向溢出。
- 焦点环、禁用、错误、选中和暂停均不能仅靠颜色表达；拖放不是唯一操作入口。

## 交付与验证边界

1. 设计方向比较页：相同内容下比较三种布局。
2. 选定方向的可点击前端设计稿：使用明确标注的合成事项，不连接真实工作空间。
3. 设计说明：信息架构、核心流程、组件规范、状态和响应式行为。
4. 浏览器检查：宽窗口、窄分屏、浅深主题，记录连续录入、筛选、选中、阶段调整、草稿保护和错误恢复路径。
5. 若进入正式界面实施，另行确认设计并执行 `pnpm check` 与 UI 浏览器检查；设计稿通过不等于真实思源窗口验收完成。
